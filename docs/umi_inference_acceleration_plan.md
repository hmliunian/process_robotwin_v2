# UMI 快速推理接入方案

状态：已获用户同意实施。日期：2026-10-20。基线分支：`feat/umi-h200-batch`。
用户随后要求在新分支 `feat/umi-inference-fast` 开发，并将首轮真实模型验收改为固定 10 帧。
当前实现及实测范围见 [10 帧验证报告](umi_inference_fast_10frames_20261020.md)。

目标是在保留现有物体定义、候选 QC、时序 QC 和产物合同的前提下，减少 SAM 的准备与传播成本，
并让不同 episode 的 Qwen 规划、SAM 处理和可视化重叠执行。优先接入单帧种子分割与视觉特征
快路径，再接入跨组常驻模型和有界异步队列；batch4 作为可选项。

本文件记录批准的接入方案。实施在独立 worktree 进行，原工作区的未提交改动保留。
本轮真实模型对照使用同一组 10 帧和冻结提示、seed，不调用 Qwen；下文十任务完整清单的
重复实测作为后续扩展验收，不属于本轮已完成结果。

## 当前基线

目标分支提交为 `cded0223b3c49e047c3ae0179b3c4b598a4d8a0c`。当前工作区还包含
`sam3_adapter.py` 和对应测试的未提交改动：文本种子查询已经对规范 JPEG 目录只加载候选单图。
后续对照以这个实际工作区状态为起点，保留这些改动，不将它们当成待新增的性能收益。

当前执行路径见 [UMI 批处理说明](umi_batch.md) 和 [架构合同](architecture.md)：

- `scripts/run_umi_batch.py` 按动作及分辨率分组，逐组调用现有 dataset workflow。
- 每组内部已有按 GPU 的常驻 SAM worker，但 worker 的配置和生命周期绑定该组。
- 单个 worker 顺序完成 Qwen 规划、种子分割及 QC、传播、时序 QC 和保存。
- 一组推理结束后生成 overlay 与 review sheets，然后进入下一组。
- UMI 输入是 `video_window`，只处理物体，不执行 URDF 或 gripper 推理。

因此新增收益应来自：补齐非文本种子的单图路径、减少传播中的多余检测计算、减少组间模型
重载和启动成本，以及隐藏跨 episode 的规划与渲染等待。

## 实验依据与采用决策

以下都是已有实验的测量值，不是目标分支接入后的速度承诺。所有实验均运行于共享 H200，
存在其他 GPU 计算进程；不同报告的绝对耗时不能直接相减计算收益。

| 来源 | 已有结果 | 接入决策 |
| --- | --- | --- |
| `perf/inference-timing-10tasks` | UMI 固定 10 类、2,399 帧，8 条完成；全部尝试平均 97.44 秒。成功样本的 SAM 传播占 33.78%，会话准备占 25.36%。 | 采用固定样本与分项计时方法，优先优化 SAM；该报告每任务重载模型，不作为新流水线的公平对照。 |
| SAM 种子单图 S1 | 固定提示集平均 8.411 → 0.749 秒/任务；42 组提示集、180 个候选 mask 逐像素一致。 | 优先采用，补齐 bbox 和文本加 bbox；当前文本补丁已经实现的部分不重复计收益。 |
| SAM 视觉快路径 T1 | 固定 seed 传播平均 32.541 → 20.058 秒/任务，时间减少 38.36%；输出与基线逐像素一致。 | 首批采用，作为默认候选。 |
| SAM 帧编码 T4 | 传播平均 18.463 秒/任务；相比 T1 再减少 7.95% 时间，部分任务回退；测试中输出一致。 | 保留开关，组合验证后决定是否启用。 |
| SAM3.1 M31 | 本次配置传播平均 37.622 秒/任务，慢于 SAM3 基线；存在 mask 和 QC 差异。 | 本轮不采用。 |
| `perf/umi-async-queue` | 常驻串行 885.37 秒，异步 725.80 秒；规划等待 70.83 → 6.25 秒，规划及渲染与 SAM 父阶段重叠 80.95 秒。 | 采用常驻和有界重叠机制，并重新测量完整流程。 |

异步实验两轮输出就绪数为 10 → 8，输出就绪吞吐为 0.678 → 0.661 条/分钟。Qwen 决策、
救援次数和传播结果发生变化，因此不能把墙钟下降 18% 当作同质量调度收益，也不能由这一次
对照判断异步导致质量下降。单卡结果尚不能证明多 GPU 的扩展效率。

SAM 微基准冻结提示和 seed，重复三次；其速度不含 Qwen、模型加载、产物保存和可视化。
S1 与 T1 的阶段加速比不能相乘，也不能与异步报告的吞吐比相乘作为端到端结果。

## 第一批接入单帧种子与视觉快路径

### 完善单帧种子分割

保留当前文本单图补丁，将资源选择逻辑集中到一个辅助函数，覆盖文本、bbox、文本加 bbox
三种请求。只有候选帧与 JPEG 顺序明确对应时才加载单图，将源帧号映射为图内第 0 帧；
目录含糊、资源类型不支持或帧不完整时回退原视频路径。

源帧范围校验在映射前执行，重复 query 仍去重并复用本次会话，异常退出仍关闭 session。
解码允许的 surplus 尾帧不改变权威帧数。种子来源、最终 mask 尺寸和原视频帧号保持对应。

这里采用实验 S1 的命名；它与项目候选解析链中的 S1/S2/S3 阶段不是同一个概念。

### 接入传播视觉快路径

原生 mask 传播已有固定对象和 seed，不需要逐帧运行随后被丢弃的完整检测分支。
采用实验分支的视觉特征路径，首轮编码 batch 为 1，即 T1。

保持原视觉主干、BF16 转换、投影、位置编码、seed 安装、双向传播和逐帧记忆更新。
替换 hook 只在一次传播作用域内生效，退出及异常均恢复；特征缓存有明确上界。
为固定的 SAM3 上游接口增加兼容性检查，接口不匹配时明确报错，不能静默使用未经验证的路径。

快路径必须通过配置到达实际 backend 构造处，包括单进程、GPU worker 和新批次入口。
避免仅在 benchmark 中启用，而实际 UMI 推理仍走原路径。优化策略和辅助模块代码身份应进入
运行记录及恢复校验。

### 单独保留 batch4

T4 对单条视频最多 4 帧组成真实张量 batch，视觉编码后仍逐帧更新 tracker，正反方向分别处理。
它不是跨视频 batching，也不把多个角色放进同一个可变 tracker。

先验证 T1，再单独开启 T4。已有实验中 T4 比 T1 的最大调用显存增量多约 0.785 GiB；
该数值包含会话与激活，不能视为独立部署显存预算。若接入后收益不稳定，生产候选保持 T1。

## 第二批接入常驻与异步调度

### 跨组复用模型

将已经转换好的各组 episode 组成统一任务队列，每个 GPU 对应一个持有 SAM 的进程。
worker 跨动作和分辨率组存活，由任务携带自己的 dataset binding、annotation mode、profile、
相机、episode 和原有 run ID。相同 checkpoint 和兼容的 SAM 配置才能复用同一个模型实例。

模型由同一 owner 线程构建和调用，确保线程局部 BF16 上下文一致。每个角色及 episode
独立创建和释放 session，不复用上一任务的 tracker 状态或特征。每组的对象定义与 QC 参数
来自该任务配置，不能沿用前一组的语义配置。

先验证单卡跨组常驻，再扩展现有多 GPU worker。多 GPU 属于接入后的新增验证范围，不能
直接把实验中的单卡 runner 当作现有多卡入口的替代品。

### 重叠规划与可视化

准备线程提前完成后续 episode 的时间线与 Qwen 规划；GPU owner 消费就绪任务，执行种子
分割、同步候选 QC 及 bbox 救援、传播、时序 QC 和 canonical 保存。后台渲染只读取已经
发布的文件，生成 overlay 和 review sheets，随后由协调端更新完成状态。

```mermaid
flowchart LR
    A[准备好的各组 episode] --> B[有界 Qwen 规划队列]
    B --> C[每 GPU 一个 SAM owner]
    C --> D[时序 QC 与同步保存]
    D --> E[有界后台渲染队列]
    E --> F[结果索引与输出就绪状态]
```

不同 episode 的 B、C/D、E 可以重叠。同一角色仍先通过候选 QC 才传播；同一 owner
同时只处理一个 SAM 调用。mask 保存保持同步，后台队列传递路径和小型元数据，不传整段
RGB、mask 数组或 GPU tensor。

| 参数 | 单卡起始方案 | 约束 |
| --- | --- | --- |
| 传播编码 batch | 1 | 4 为独立可选对照；保留原传播路径供比较和回退。 |
| 规划 outstanding 上限 | 2 | 限制运行中与已就绪规划之和，避免结果提前堆积。 |
| Qwen 请求上限 | 4 | 规划、候选 QC、bbox 救援共用限流；多 GPU 时仍是整批共享上限。 |
| 规划线程 | 2 | 单卡可为同步 QC 留出容量；多卡共享请求上限，不提供全局 QC 优先级。 |
| 渲染线程及 outstanding 上限 | 1 / 2 | 队列满时施加背压，批次结束等待全部渲染完成。 |
| CPU 线程 | 对照时固定为 8 | 与已有实验口径一致，不代表已找到最优线程数；多进程同时控制总 CPU 预算。 |

参数通过 UMI 入口显式启用，具体 CLI 见 [快速推理用法](umi_batch.md#快速推理)。
配置可分别控制原传播/T1/T4、串行/异步，并记录生效值；其他工作流另行验证。

### 保持产物与恢复逻辑兼容

实验异步入口使用每 episode 的 run ID，而当前批次使用分组 run ID。接入时保留当前分组
目录、episode 来源、结果索引和合并工具的读取约定；内部调度键使用组、episode、相机的
组合，不能直接搬用实验目录布局。

协调端统一更新批次及分组 ledger。渲染线程返回结果，不并发覆写共享索引；组级 review
sheets 使用已确定的结果快照生成。只有 masks、所需 overlay 和 review sheets 齐备时才计为
输出就绪，完成状态继续为 `needs_temporal_review`。失败任务保留诊断与原始 RGB 检查图。

恢复前校验完整 selection、输入身份、权重、配置、prompt 和实现指纹。有效 masks 允许只补
渲染；更改优化策略时必须验证身份兼容，不能以旧结果证明新路径正确。中断或 fatal CUDA
后保留已完成、失败、取消和未执行任务，关闭 backend 并恢复请求限流器。

## 实施顺序与代码范围

| 步骤 | 工作 | 进入下一步的条件 |
| --- | --- | --- |
| 0 | 固定当前分支与未提交补丁，记录代码、配置、权重和输入身份，建立当前基线。 | 能明确复现优化前状态，已有未提交文件不被覆盖。 |
| 1 | 完善三类 seed 单图请求及对应回退，验证相对当前文本补丁的剩余收益。 | 候选 mask、帧映射与 QC 一致。 |
| 2 | 接入可配置 T1，贯通实际 backend 构造路径。 | 固定 seed 传播逐像素一致，阶段计时改善。 |
| 3 | 每卡一个 worker 跨组常驻，暂保持串行规划和渲染。 | 跨组配置正确，模型加载次数符合预期，session 无串扰。 |
| 4 | 启用有界规划预取与后台渲染，完善 ledger 和恢复。 | 队列容量、实际重叠、完成状态及错误路径验证通过。 |
| 5 | 在稳定组合上单独比较 T1/T4，再验证多 GPU。 | 完整输出吞吐提高，质量和内存检查通过；否则保留较简单配置。 |

实现以最小功能单元接入，不整包合并两个实验分支，不引入 SAM3.1 和无关分析产物。

预期涉及以下文件或模块；具体拆分以保持现有职责边界为准：

- `adapters/sam3_adapter.py` 和小型视觉特征辅助模块：单帧资源选择与 T1/T4。
- `config.py`、UMI 配置绑定、backend 构造处：策略校验、传递与运行身份。
- `application/parallel_sam_runtime.py` 和必要的 UMI 编排模块：跨组任务及模型所有权。
- `scripts/run_umi_batch.py`：沿用当前入口、分组输出、状态与 review 流程。
- 计时及离线汇总辅助：提取固定 manifest 和必要测量逻辑，避免依赖模型服务做汇总。
- 对应单元/集成测试，以及实施后的架构和操作说明更新。

四通道 `[4,T,H,W]` bool masks、visible 编码、角色约定与 source provenance 保持现有合同。
不降低分辨率、不跳帧、不减少必要角色、不关闭 QC，也不以缩短失败路径冒充性能提升。

## 验证与验收

首轮按用户最新要求，对 pour/episode 500/cam_high 的前 10 帧进行三轮配对测量，
计算 target 和 receiver 的逐帧 IoU，并分别比较种子请求和传播耗时。基线包含原文本单图
补丁；异步与多 GPU 调度通过 CPU 流程回归验证。具体结果和边界以实测报告为准。
以下保留后续完整清单验收方法，本轮未运行十任务真实 API 对照。

### 固定决策的计算与调度验证

首轮使用已有的 10 类 UMI 清单，640×480、`cam_high`，各 1 条，共 2,399 帧。
清单来自 `perf/inference-timing-10tasks` 的 `configs/datasets/inference_timing_umi_10tasks.json`。
保留 pull、scoop 等历史失败样本，缺失合法 seed 的角色明确标为 N/A。

冻结已保存的提示、bbox、QC 决策及 seed，分别比较当前基线、单图扩展、T1 和可选 T4。
调度对照使用相同冻结决策和传播工作量；明确标为控制实验，不冒充实时 API 结果。
核查候选及逐帧 mask、seed、帧序、窗口和 QC issue 集合；要求固定决策下 S1/T1 输出
逐像素一致。T4 如有未解释差异，保持关闭，保留差异证据。

该验证包含非零 seed、正反向传播、最长 519 帧窗口、单角色和双角色任务。其他分辨率在
实际启用前补充代表性验证，640×480 的结论不自动推广。

### 真实 API 的完整流程验证

使用同一份十任务清单，分别比较当前状态、第一批优化、跨组常驻、常驻异步及可选 T4。
每组使用新输出目录，保持同一 GPU 分配、CPU 预算、checkpoint、QC 和输出要求。
关键对照重复三次并轮换顺序，记录资源争用，不删除慢样本或失败样本。

常驻串行和常驻异步必须使用相同的模型生命周期。若实时 Qwen 决策造成工作量或质量结果
变化，分别记录请求数、救援次数、传播次数和失败原因；将原始吞吐结果与固定决策对照分开
解释，不能据此直接归因于调度。

| 指标 | 口径与用途 |
| --- | --- |
| 批次墙钟 | 从 runner 开始至模型释放、保存和全部渲染结束；包含所有失败成本。完整进程时间另记。 |
| 完整输出吞吐 | masks 与所需可视化齐备的条数 / 批次分钟数；作为主要速度指标。 |
| 完成数与失败分布 | 保留全部选中任务与必需角色，检查是否因少完成或少传播而变快。 |
| 单任务耗时 | 分开记录排队等待、各阶段服务时间和首次入队到 review 就绪的延迟；不以墙钟除任务数代替延迟。 |
| 阶段与重叠 | 模型加载、seed session、种子分割、传播、Qwen、保存、渲染；父子阶段去重，重叠区间取并集。 |
| 资源 | 加载次数、实际编码 batch、缓存上界、进程显存增量、CPU 预算及同卡竞争。 |
| 输出一致性 | 固定决策的像素差异、非空帧、QC、四通道合同与来源身份；相似度不作为人工真值准确率。 |

启用条件是：合同和固定决策一致性通过，重复对照支持完整输出吞吐提升，无新增未解释的
质量或恢复问题。实时 API 下质量不等价的结果单独报告；证据不足时不将异步或 T4 设为默认。
不预设“整体两倍”等未测得目标，最终报告给出相对当前实际基线的结果。

### 自动检查与人工检查

CPU 回归重点覆盖单图帧映射及回退、所有构造入口的配置传递、双向缓存及 hook 恢复、跨组
profile 隔离、队列背压、全局请求限流、中断/fatal CUDA、部分渲染失败和 selection 恢复校验。
重点验证原有批次索引、review 和分辨率合并工具仍可读取新执行结果。

实施后运行相关回归、完整 CPU 单元套件、Ruff 和类型检查；全量检查出现已有基线错误时
记录与变更的关系。真实模型产物抽查至少一个单角色任务、一个双角色任务和失败样本，保留
task、camera、episode、seed 与最差差异帧的 review 证据。自动完成仍不等同于人工逐帧验收。
